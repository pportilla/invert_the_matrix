Guide

How to Play

Clear the board by making every tile return to calm zero. Each tap sends a pulse through a pattern, and every touched tile advances by one state.

1. Read the tiles

A pale tile is solved. Colored tiles show values \(1,2,3,\ldots\), depending on the number of states in the level.

2. Tap and wrap

Tap a tile to add \(1\) to every tile in its pulse pattern. After the last color, the next tap wraps that tile back to zero.

3. Watch the pattern

Different levels use cross, diagonal, square, horizontal, vertical, knight, or mixed pulse patterns. Hold or hover a tile to preview its affected tiles.

4. Respect special tiles

Locked tiles can be changed by nearby pulses, but you cannot tap them directly. Empty holes are outside the board and do not store a value.

Moves, stars, and hints

The move counter counts every tap. Three stars means matching the generator's minimum found move count; two, one, and zero star bands allow progressively more extra moves.

Undo rewinds one move, Reset restores the starting board, and Hint applies the next move from a solver plan. A hint makes that try worth zero stars, but the puzzle still counts as complete. Tiles changed by a hint are marked in red.

Guide

The Math

Invert the Matrix is a spin on the classical Lights Out puzzle, but the useful way to see it is not as a picture of tiles. It is a list of numbers. A tap adds one fixed move vector to that list, and the puzzle asks whether some sum of move vectors cancels the starting board.

All arithmetic is modular. If a level has \(n\) states, then tile values live in \(R=\mathbb Z/n\mathbb Z\), so the value after \(n-1\) wraps back to \(0\). Prime moduli such as \(2,3,\) and \(5\) give finite fields. The four-state mode lives in the ring \(\mathbb Z/4\mathbb Z\), where addition still behaves beautifully, but not every nonzero number can be divided by.

\[ A x \equiv -s \pmod n \]

From Lights Out

A modular version of the same question

In ordinary Lights Out, every tile is either \(0\) or \(1\), and pressing a tile toggles a fixed neighborhood. Toggling is the same thing as adding \(1\) modulo \(2\), so pressing the same tile twice gives no net change. That is linear algebra over \(\mathbb F_2\).

This game keeps the linear structure but changes the arithmetic. A level with \(n\) states works in \(R=\mathbb Z/n\mathbb Z\). The board may have locks, gaps, and different pulse patterns, but the question remains the same: can the allowed move columns add up to the negative of the current board?

1. The board is a vector

Ignore gaps and list the active tiles in a fixed order. Their current values form a vector \(s\in R^m\), where \(m\) is the number of active board positions. The pale solved value is \(0\), so solving the puzzle means reaching the zero vector.

\[ s=(s_1,\ldots,s_m),\qquad s_i\in \mathbb Z/n\mathbb Z \]

2. Every legal tap is a column

The move matrix \(A\) has one column for each tile you are allowed to tap. Column \(j\) records the board change caused by tap \(j\). The entry \(A_{ij}\) is \(1\) if tap \(j\) changes tile \(i\), and \(0\) otherwise.

Locked tiles still appear as rows because their values must become zero, and nearby moves can change them. They do not appear as columns because they cannot be tapped directly.

\[ A_{ij}= \begin{cases} 1 & \text{tap }j\text{ changes tile }i,\\ 0 & \text{otherwise.} \end{cases} \]

Goal

Find a tap vector

A plan is a vector \(x\in R^r\), where \(x_j\) says how many times to use legal tap \(j\), counted modulo \(n\). Because the moves add together, the order of taps does not matter algebraically; only the number of times each legal tap is used matters.

After the plan, the board is \(s+Ax\). Solving the puzzle means making that vector zero, which is the same as solving the linear congruence \(Ax\equiv -s\pmod n\).

\[ s + A x \equiv 0 \pmod n \] \[ A x \equiv -s \pmod n \]

When does a solution exist?

The columns of \(A\) describe all board changes reachable by legal moves. The clean answer is image membership: the target vector \(-s\) must be in the image, or column span, of the move matrix \(A\).

\[ \text{solution exists} \Longleftrightarrow -s\in \operatorname{Im}(A) \]

Over a field, such as \(\mathbb F_2,\mathbb F_3,\mathbb F_5\), this can be checked by row-reducing the augmented system \([A\mid -s]\). A row that says \(0=\text{nonzero}\) means no solution. If no contradiction appears, back-substitution gives at least one tap plan.

What changes for non-prime \(n\)?

For composite \(n\), \(\mathbb Z/n\mathbb Z\) is usually a ring, not a field. You may add and multiply as usual, but you cannot divide by a non-unit. For \(n=4\), \(2\) is nonzero but has no inverse: no value \(a\) satisfies \(2a\equiv 1\pmod 4\).

\[ 2a\not\equiv 1\pmod 4 \]

The criterion does not change: there is still a solution exactly when \(-s\in\operatorname{Im}(A)\), but the verification must respect ring arithmetic. Row operations that divide by non-units can invent false conclusions. For general composite \(n\), one can also check the compatible prime-power systems given by the Chinese remainder theorem.

When is the solution unique?

If \(x_0\) is one solution, then every other solution is \(x_0+z\), where \(z\) is a vector of moves that changes nothing. These silent plans form the kernel of the move matrix.

\[ \{x:\ Ax=-s\}=x_0+\ker(A) \]

So the algebraic solution is unique precisely when \(\ker(A)=\{0\}\). Over fields this is the same as saying the legal tap columns of \(A\) are independent. Over rings, the same kernel condition is the right statement, but it must be checked in the module over \(\mathbb Z/n\mathbb Z\).

Why the minimum matters

If there are several algebraic solutions, the game can still ask for the most efficient one. The star target is based on a representative with the smallest total number of physical taps. Using representatives \(0,\ldots,n-1\), the length of a plan is the sum of those tap counts.

\[ \min \|x\|_1 = \min \sum_j x_j \]

Locked tiles and gaps

Locked tiles still appear as rows because their values must become zero, and nearby moves may change them. They do not appear as tap columns. Gaps are removed from the board, so they are neither rows nor columns. This is how the same equation adapts to irregular boards without changing the underlying idea.

How the generator uses this

The generator builds \(A\) from the board shape, locks, gaps, and pulse pattern. It chooses or checks a starting vector \(s\), verifies that \(-s\) lies in \(\operatorname{Im}(A)\), and stores a solving plan. For curated levels it also searches for a short representative so the star thresholds have a mathematical basis. Hints use a stored plan one step at a time.

What the symbols mean
\(n\)
The number of tile states and the modulus used by the level; the app uses \(2,3,4,\) or \(5\) states.
\(s\)
The current board written as one long vector.
\(A\)
The pulse matrix. Each column is one possible tap.
\(x\)
The tap-count vector you are trying to find.
\(\operatorname{Im}(A)\)
All board changes obtainable by legal taps.
\(\ker(A)\)
Tap plans that leave the board unchanged.
